# マネーフォワードの明細を日記の参考資料にする

作成日: 2026-11-01（Asia/Tokyo）

状態: 本人が方式1を選択。設計確認待ち。実装・配置・実データ取得は未実施。

## 目的と合意した使い方

「何をした一日か」を具体的に残すため、日記を書くときに対象日のマネーフォワード MEの明細も読む。既存の会話・位置情報・予定などと合わせ、食事・買い物・移動など、資料から分かる出来事を日記に生かす。食べ物や商品が分かる記録は、その具体性を生かす。

本人は、食事内容などが分からないときに追加で聞き取ることは求めていない。明細を加えることによって、確認質問や毎日の作業を増やさない。通常の一日全体の振り返りは既存の流れを使う。

## 検討した方式

| 方式 | 利点と制約 | 選択 |
|---|---|---|
| 1. 日記を書くときに対象日の明細を読む | 既存のカレンダー等の都度参照と同様に、小さなスキル変更で始められる。後日読む場合は、その時点で取得できる資料を使う | 本人が選択 |
| 2. 明細も日別に保存する | 後から再利用しやすいが、保存形式や更新の仕組みが必要になる | 今回は採用しない |

## 小さな変更として実装する範囲

中心は `skills/daily-diary/` の手順追加。`references/moneyforward.md` に明細の読み方をまとめ、`SKILL.md` と `references/collect.md` の資料収集・振り返り・統合につなぐ。`references/diary-format.md` とREADMEにも、出来事の具体化と出典の扱いを反映する。既存の架空受入ケースへ確認項目を追加する。

既存のマネーフォワード MEプラグインを使う。収集用Pythonコード、collect-activityのスキーマ、runtimeの日別JSON、定期実行は変更しない。明細の別途保存や新たな個人設定・資格情報は追加しない。資産残高・保有銘柄・月間収支の取得、家計評価や節約提案は今回の対象に含めない。

配置済みスキルは既存の配置手順に沿って退避・同期し、リポジトリとの一致を確認する。実装の検証、配置、実データの読み取り確認は別の結果として扱う。日記本文のNotion保存は、引き続き最新全文への本人の明示的な承認後に行う。

## 明細の読み取り

- 日記の対象日は既存のAsia/Tokyoの扱いに合わせる。`list_transactions` の `from_date` と `to_date` に同じ `YYYY-MM-DD` を渡し、対象日だけを取得する。APIの両端を含む日付指定へ翌日を渡さない。
- 現在のツール定義では、振替以外の収入・支出について、日付・内容・金額・カテゴリ・口座情報が返る。時刻や品目の明細、店舗の詳細、全振替を取得できるとは扱わない。商品名等は返された内容や他の資料に実際にある場合だけ使う。
- 今日の分は取得時点の途中経過として扱う。ツールは日付単位のため、日記開始時刻を上限とする厳密な時刻絞り込みはできない。対象日・取得時点・読み取り状態・主な制約を出典へ短く残す。
- 登録された明細の日付を、そのまま来店・食事・利用の実施日時に変えない。遅れて反映される可能性や利用日不明の記録を考慮し、他の資料から対象日の出来事として結び付く範囲を使う。引落し・チャージ等を当日の食事や新たな買い物に読み替えない。
- 取得できた0件と取得不能を区別する。0件でも、その日の支払いや行動がなかったとはしない。未接続・認証待ち・利用可能期間外・件数上限等で取得できなければ、不足を短く示して既存資料で続ける。通常の日記作成で接続設定や無制限の再試行を始めない。
- 本人が「保存済み資料だけで」と指定した場合は、新たなプラグイン取得をしない。複数日の日記も既存どおり一日ずつ扱う。

## 出来事への統合

明細は食事・買い物・移動などの候補を増やし、既存の同じ出来事を具体的にする資料として使う。位置情報・予定・本人の発言等と結び付く場合は一つの出来事にまとめ、資料の数だけ同じ行動を増やさない。

料理・商品名が記録にあれば拾う。ただし、購入の記録から本人が食べたこと、同行者、感情や目的まで作らない。店名・カテゴリ・金額だけからメニューや商品、支店、朝昼夜や移動経路を補わない。既存資料や本人の発言で食事内容まで確認できる場合は、その具体的な内容を残す。

日付や用途が曖昧なものは分かる粒度にとどめる。曖昧さを埋めるための追加質問、全明細の確認、レシート等の追加収集は行わない。初回の出来事紹介は既存の3〜5項目程度を保ち、明細を一件ずつ読み上げない。

本文は既存の「今日のこと」「仕事／個人開発／その他」に出来事ごとにまとめる。家計欄や明細一覧は新設せず、金額はその出来事を伝えるのに役立つときだけ残す。出典は末尾の折りたたみに、マネーフォワード ME・対象日・取得時点と、必要な内容／日付／金額等の照合情報を最小限で記す。口座情報や明細全件を転載しない。個人の実資料をGitへ保存しない。

## 実装担当に任せることと確認方法

参照文書へのリンク位置や文言の分量は、既存のスキル構成に合わせて決める。新しいAPIクライアントや保存処理は作らない。

架空資料で、具体的な食事内容がある場合、店名だけの場合、購入と飲食の違い、他の資料と同じ出来事、利用日不明の引落し、当日分の途中経過、0件・取得不能、保存済み資料のみの指定を確認する。追加質問を増やさず、不明点を補作しないことを確かめる。スキル形式と `git diff --check` を検査し、配置後はファイルの一致を読み戻す。

実データの確認が必要になった場合は、対象日を具体的にして読み取り結果を確認し、架空資料の検証や配置だけで接続・実運用まで確認済みとはしない。
