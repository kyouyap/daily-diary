# 会社用の振り返りスキル設計

状態: 設計案。本人の確認前。スキルは未実装。

## 目的と合意した内容

会社での仕事の証跡を残し、それを材料に本人が一日を振り返る。日々の「自分がしたこと・結果や現在地・証跡」を中心に記録する。

- 個人用の `daily-diary` とは別のスキルを用意する。
- 会社のMac版ChatGPTデスクトップアプリから使う。
- 資料はNotion、Slack、ClaudeとChatGPTの会話履歴、Computer History。
- 日誌を作るときに対象日の資料を参照する方式Aを使う。
- 判断・難しかったこと、本人の振り返り、次の行動は必要に応じて補う。
- まず本人の振り返りに集中する。チームへの共有方法は今回の設計対象に含めない。

## 検討した方法

| 案 | 方法 | 利点と負担 |
|---|---|---|
| A: 実行時に参照 | 振り返りを始めたときに対象日の資料を読み、日誌に根拠リンク・識別情報を残す | 導入が軽い。読み取れる範囲は会社側の接続環境に依存する |
| B: 資料も日別保存 | 参照資料の写しも日付ごとに保存して使う | 当時の資料を再確認しやすい一方、保存処理・管理が増える |

本人はAを選択した。資料の新しい日別アーカイブや収集用の定期実行は追加しない。既にあるComputer Historyの記録は資料として参照する。

## 日誌作成の動き

1. 対象日と期間を固定する。指定がなければ日本時間の今日0時から実行開始時点まで。過去日はその日の0時から翌日0時まで。
2. 設定された会社側の接続で資料を読む。同日の既存日誌があれば本文と本人の追記も読む。
3. 同じ課題・目的の資料を一つの取り組みにまとめ、自分の行動、結果・現在地、証跡を整理する。
4. 主な取り組みを短く紹介し、本人に一日を振り返ってもらう。話した内容に沿って必要な点だけ一問ずつ聞く。「まとめて」と言われたら本文へ進む。
5. 証跡と取得範囲も含めた全文を提示する。保存先と新規作成・同日更新の別を示す。
6. 最新全文への本人の明示的なOK後に会社側のNotionへ保存し、本文と日付・リンクを読み戻して照合する。

各取り組みで「日付・取り組み」「自分がしたこと」「結果・現在地」「証跡」を中心に残す。証跡がない活動も本人の補足として残せるが、資料で確認した事実とは区別する。判断理由、難しかったこと、学び、次にすることは、本人の話や記録にある場合に加える。全項目を埋めるための質問や推測は行わない。

## 資料ごとの扱い

| 資料 | 拾う内容と確認の境界 |
|---|---|
| Notion | 仕様・設計・議事録・本人の記述。ページの最終更新日だけで、その日に本人が作業・決定したと断定しない |
| Slack | 本人の相談・提案・調整・支援と、本人が関与した決定。関連スレッドを文脈として読み、他人の発言を本人の実施に変えない |
| Claude / ChatGPT | 本人の依頼・指摘・検討・判断と試行錯誤。本人の発言、AIの提案・完了報告、実物で確認できた結果を区別する |
| Computer History | 作業の流れと抜けた活動の手掛かり。画面表示、入力、保存、送信、作業完了を区別する |

専用の接続が利用できる資料はその読み取り機能を優先する。Claude・ChatGPTの会話履歴については、会社側で使える接続や、許可されたログイン済みアプリ・ブラウザの読み取り経路を確認してから使う。ChatGPTから全会話を自動取得できるとは前提にしない。

### 会話履歴の具体的な取得候補と検証

現時点の候補は、会社のログイン済みChromeをChatGPT WorkのChrome操作から読み、Claude・ChatGPTそれぞれの会話一覧や検索画面で対象会話を開いて本文を参照する方法。これは会社環境では未検証であり、採用済みの取得経路とは扱わない。

確認できた公式機能と、その境界は次のとおり。

- ChatGPTには、過去の会話を開くためのSearch chatsがある。これは画面上の検索機能であり、会社用スキルに全会話取得のAPIが提供されるという意味ではない。[公式説明](https://learn.chatgpt.com/docs/reference/commands)
- ChatGPT Workには、許可されたアプリやログイン済みChromeの画面を読む機能がある。ただし、会社側での利用可否や各サービスの会話本文を実際に読めるかは別に確認する。[公式説明](https://developers.openai.com/training/walkthroughs/using-your-computer-and-browser)
- Claudeには、Claude自身が過去の会話を検索・参照する機能がある。ChatGPTから直接呼べる連携として確認できたわけではない。[公式説明](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)
- Claudeには会話データの公式エクスポートがある。Team・Enterpriseでは組織側の設定に依存し、エクスポートの生成後にメールのリンクからダウンロードする。都度の資料参照を選んだ今回の通常経路には採用せず、別の選択肢として扱う。[公式説明](https://support.claude.com/en/articles/9450526-export-your-claude-data)

会話の新規送信やエクスポート申請を、資料の読み取りとして自動実行しない。メモリーの要約やComputer Historyだけで会話全文を取得したとは報告しない。

スキルの取得手順を確定する前に、本人が指定する既知の日付の会話をClaude・ChatGPTそれぞれ一件ずつ使い、本文、対象日の判別、元の会話へのリンクを確認する。長い会話は前半も読めるか確認する。少数の会話を読めても対象日全体の網羅性を確認したとは扱わない。この実機確認はまだ行っていない。

読めない資料があっても、取得範囲と主な欠落を短く伝え、読めた資料と本人の話で進める。日時不明は当日に補わず、未取得を「活動なし」にしない。Computer Historyは実際の記録状態と対象期間を確認する。

証跡は元のページ・メッセージ・会話へのリンクを基本とし、必要なら日時、会話やイベントのID、確認箇所を併記する。直接リンクが得られない資料にURLを捏造しない。単に一覧が見えたことを全件取得とせず、部分取得はその範囲を残す。

## 会社用としての配置と初回設定

既存の個人用スキルから、対話・事実の整理・全文確認・保存後照合の考え方を使う。個人用の保存先ID、アカウント、ローカル設定、Langfuse、X、YouTube、位置情報、メール等は継承しない。

会社側で初回に、対象ワークスペース、本人の識別に使うアカウント、Notionの保存先、使用できる接続を指定して使う。接続先や保存先を推測・自動作成しない。会社固有の設定はスキルの配布物やGitへ含めない。

スキル本体と必要な参照手順を追加する範囲とし、新しい収集サービスやAPI連携の実装は含めない。接続の導入が必要と分かった場合は、今回のスキル作成と分けて扱う。

## こちらで置いた初期案

- スキル名は仮に `work-diary` とする。
- ChatGPT Workから呼び出す。
- Notionは一日一ページ、タイトルは `YYYY-MM-DD` とする。既存の保存先の構造に合わせ、通常実行でDBやビューを改造しない。
- 同日更新では既存本文と本人の追記を保ち、統合した全文を再確認する。
- 訂正が入った場合は最新全文を再表示する。書き込み結果が不明な場合は先に読み戻し、新規作成・追記を自動で繰り返さない。
- 元資料を改変せず、会社の記録・日誌本文・資格情報をGitに入れない。
