# 活動記録の収集と日記活用 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The user has not selected an execution method or approved execution. Do not start implementation yet.

**Goal:** 日記と独立して活動記録をローカルの日別JSONへ蓄積し、取りこぼし回収と本人との振り返りに使えるようにする。

**Architecture:** 収集スキルが取得・判断を担い、小さなスクリプトが保存と進捗を担う。メールとカレンダーは日記作成時に取得する。Screen Timeの既存収集は維持する。

**Tech Stack:** 実装候補はPython 3.12の標準ライブラリ、JSON、unittest、Codexスキル、既存のChrome操作・接続、macOSの実行管理。採用はTask 1の確認を経る。追加の有料API・別のAI APIは導入しない。

**Spec:** [承認済み設計](../specs/2026-10-16-activity-collection-design.md)。設計の承認は、未決定事項の承認や実装開始を意味しない。

## Global Constraints

- 「実データ・認証情報・個人固有の設定をGitへ入れない。」
- 「停止中の日記自動実行は再開しない。」
- 「一日1回、直近数日を取り直す。Screen Timeの既存15分間隔は維持する。」
- 「ログイン切れはその対象だけ保留し、ほかの資料は続ける。」
- 「YouTube Musicは初回取得日のファイルに保存し、再生日時は不明」
- 「Xの編集履歴は扱わない。」
- 「収集だけの実行では日記やNotionページを自動作成しない。」
- 日付境界はAsia/Tokyo。元の日時の精度・タイムゾーンが不明なら推定で補わない。
- この計画の現段階で許されている変更は文書のみ。実機の再設定・収集開始・定期実行登録は行わない。

## Review Focus

- 日付不明の同じ曲・リポストを再取得しても初回取得日を動かさない（Task 2）。
- JSON保存後・進捗更新前の停止から、重複も取得漏れの隠蔽もなく回復する（Task 2）。
- 非公開アカウントを読み終える前に失敗しても、別アカウントの内容を本人の対象投稿と取り違えない（Task 3）。
- ブラウザが途中で読み込めなくても「投稿なし」「全件取得」と報告しない（Tasks 3・4）。
- Mac復帰時と日次起動が重なっても二重操作せず、ログイン待ちの対象だけ保留する（Task 6）。

## 段階と着手条件

この計画は収集基盤、資料別収集、日記連携、運用導入に分ける。各段階で独立した検証結果を残す。実装前にTask 1で未決定事項を解消する。確認結果で構成が変わる場合は、設計と該当タスクを更新してから承認を得る。検証不能な部分を架空の呼出方法で埋めない。

特に、Macの起動管理からデスクトップ版CodexとChromeへつなぐ経路は未確定。これが成立しない場合はTask 6を進めず、手動収集までを独立した成果として扱う。無人実行を実現済みとしない。

## Task 6: 日次起動と取りこぼし回収を接続する

**Files:** Task 1で確定した実行方式の設定例・接続処理、`docs/collection/operations.md`、`tests/collection/test_scheduling.py`、`test_recovery.py`。

**Interfaces:** 確定した実行要求 → 対象別の未取得範囲 → 収集スキル → Task 2の保存・状態。接続方式を確定するまでコード作成に着手しない。

- [ ] 日次を逃した復帰、OS再ログイン、長期停止、重複起動、一対象の認証切れとほかの成功、状態変化時だけの通知を検証するテストを先に失敗させる。
- [ ] 合意した実行経路へ接続し、日次と復帰で同じ未取得判定を使う。ブラウザ操作は直列、既存の日記自動実行は再利用・再開しない。
- [ ] テスト成功後、一回限りの実行でアプリ終了・Chrome接続不可・ログイン切れを区別する。復帰検証のためのスリープやアプリ終了は本人と実施時点を調整する。
- [ ] 設定例と実施結果を提示する。常設の定期実行登録は、その具体的な時刻・対象・通知先の承認を受けた後に別手順として行う。
