# 活動記録の収集と日記活用 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute this plan task-by-task in the current chat, as selected by the user. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks 1–5, 7–8 have repository implementations and synthetic verification. Task 6 remains deferred; do not register scheduling or change deployed skills/environment.

**Goal:** 日記と独立して活動記録をローカルの日別JSONへ蓄積し、取りこぼし回収と本人との振り返りに使えるようにする。

**Architecture:** 収集スキルが取得・判断を担い、小さなスクリプトが保存と進捗を担う。メールとカレンダーは日記作成時に取得する。Screen Timeの既存収集は維持する。

**Tech Stack:** 提案はPython 3.12の標準ライブラリ、JSON、unittest、Codexスキル、既存のChrome操作・接続。macOSの無人実行接続は別段階で確定する。追加の有料API・別のAI APIは導入しない。

**Spec:** [承認済み設計](../specs/2026-10-16-activity-collection-design.md)。設計の承認は、未決定事項の承認や実装開始を意味しない。

## Global Constraints

- 「実データ・認証情報・個人固有の設定をGitへ入れない。」
- 「停止中の日記自動実行は再開しない。」
- 「毎朝7時（Asia/Tokyo）、当日と過去3日分を取り直す。初回は過去30日分を取得できる範囲で回収する。Screen Timeの既存15分間隔は維持する。」
- 「ログイン切れはその対象だけ保留し、ほかの資料は続ける。」
- 「YouTube Musicは収集対象外。」
- 「無期限ローカル保存。バックアップもこのMac内のみで、外部・クラウドへ自動転送しない。削除の細かな仕組みは今回の設計対象外。」
- 「対応が必要な変化はCodex上で通知し、同じ問題の通知は繰り返さない。」
- 「日記前のテーマ提示は3〜5項目・各1〜2文。確認できた事実と解釈を分け、本人の話で補う。」
- 「Xの編集履歴は扱わない。」
- 「収集だけの実行では日記やNotionページを自動作成しない。」
- 日付境界はAsia/Tokyo。元の日時の精度・タイムゾーンが不明なら推定で補わない。
- 2026-10-17に本人が保存仕様と本計画を承認。Task 2〜5・7〜8のリポジトリ内実装を進める。実機の再設定・実データ収集開始・定期実行登録は行わない。

## Review Focus

- 日付不明のリポストを再取得しても初回取得日を動かさない（Task 2）。
- JSON保存後・進捗更新前の停止から、重複も取得漏れの隠蔽もなく回復する（Task 2）。
- 非公開アカウントを読み終える前に失敗しても、別アカウントの内容を本人の対象投稿と取り違えない（Task 3）。
- ブラウザが途中で読み込めなくても「投稿なし」「全件取得」と報告しない（Tasks 3・4）。
- Mac復帰時と日次起動が重なっても二重操作せず、ログイン待ちの対象だけ保留する（Task 6）。

## 段階と着手条件

この計画は収集基盤、資料別収集、日記連携、運用導入に分ける。各段階で独立した検証結果を残す。実装前にTask 1で未決定事項を解消する。確認結果で構成が変わる場合は、設計と該当タスクを更新してから承認を得る。検証不能な部分を架空の呼出方法で埋めない。

2026-10-17の本人の指定で、追加の実機確認は保留のまま進める。Task 1では[保存仕様案](../../collection/storage-contract.md)をレビュー対象にし、調査の未完了をTask 2〜5・7〜8の実装停止理由にしない。Task 6の実行経路・常設登録は後続の独立した段階へ分け、現時点では接続コードを作らない。実行順は1→2→3→4→5→7→8とし、6は経路が確定するまで保留。

特に、Macの起動管理からデスクトップ版CodexとChromeへつなぐ経路は未確定。これが成立しない場合はTask 6を進めず、手動収集までを独立した成果として扱う。無人実行を実現済みとしない。
