# Notion保存手順

## 接続と実スキーマ

接続済みNotion MCPの取得・検索・データソース照会・作成・更新を使う。公開ツールとアクセス情報を確認し、ツール名prefixは固定しない。接続がなければ本文案まで作り、保存未実施と伝える。

- データベース: https://app.notion.com/p/96f7af28509b4818b8f182a104650bcf
- データソース: collection://6ebbdba8-5196-434b-ba54-77cd2660fe8f

fetchで所属とプロパティを確認する。下記は初期設定で、実行時の実スキーマを優先する。不適合なら勝手に新DBやプロパティを作らず不足を伝える。

| プロパティ | 型と使い方 |
|---|---|
| タイトル | title。YYYY-MM-DD｜短い判断・成果 |
| 日付 | date。対象日のJST日付、時刻なし |
| 活動区分 | multi_select。仕事／個人開発／その他。根拠のある区分を複数選択、不明は空欄 |
| プロジェクト | rich_text。確認できた名称。account_meは個人開発 |
| 状態 | select。全文確認後の保存は「確認済み」 |
| 移行元 | rich_text。新規は空欄、既存の値は保持 |

未承認本文をNotionの「下書き」に自動保存しない。「移行済み」の過去日誌も今回の全文確認なしで「確認済み」に変更しない。

## 同日ページの照会

fetchで得たcollection URLとSQL列名を使う。SQLが利用可能なら値はparamsでbindする。利用不可なら対応するrows filterやページ検索を使い、対象日と所属を確認する。検索だけで本文を推測せず、部分取得を「なし」と判断しない。

```sql
SELECT url, "タイトル", "date:日付:start", "状態"
FROM "collection://6ebbdba8-5196-434b-ba54-77cd2660fe8f"
WHERE "date:日付:start" = ?
```

0件なら新規、1件なら本文をfetchして編集候補、複数件なら対象を特定する。書き込み直前にも照会する。

## 作成・更新

最新のツールschemaを読む。本文の構文はNotion fetchで `notion://docs/enhanced-markdown-spec` を取得して確認する。

現行create_pagesのparentはDBのpage_idではなく `data_source_id: "6ebbdba8-5196-434b-ba54-77cd2660fe8f"`。日付は `date:日付:start: "YYYY-MM-DD"` と `date:日付:is_datetime: 0`。multi_selectはツールschemaに従う（SQLite形式ではJSON配列文字列）。タイトルはpropertiesに置き、本文先頭で重複させない。外部出典リンクを維持する。

既存ページは確認された範囲だけ置換・追記する。触らない本文、本人の手編集、既存プロパティを保持する。全置換は統合後の全文と範囲を本人が確認した場合に限定する。直前のfetchを確認時の基準本文と比較し、変わっていれば再確認する。これは同時編集の完全な排他制御ではない。

## 結果照合

書き込みのpage IDとURLを保持する。非同期ならタスク成功後に読み戻す。fetchで本文、外部リンク、日付、タイトル、活動区分、プロジェクト、状態を照合する。Notionの見出し・エスケープ変換だけを表示差として扱う。意図しない変更・欠落があれば完了を報告せず差を伝えて停止する。リンクだけの欠落でも自動修復しない。本人が修復を指示した場合は最新ページを再取得し、確認済み内容へ戻す最小差分だけを修復する。意味や更新範囲を変える場合は改めて本文確認を行う。

タイムアウトなど結果不明なら同じ作成・追記を繰り返さない。新規は同日ページを再照会し、更新は保持したpage IDをfetchする。承認本文が反映済みなら照合後に完了。取得不能・反映不明なら停止。未反映と分かっても状況を説明し、本人の再実行指示を受ける。部分反映を自動全置換・削除・ロールバックしない。

全文承認後の通常保存では、さらに別の保存許可を求めない。スキーマ変更・移動・共有・削除は本文承認に含めない。
