# 日誌本文の形式

ページ名は `YYYY-MM-DD` だけ。仕事・個人開発・その他の区分は活動があるものだけ表示する。プロジェクトはDB項目にせず、必要なら取り組み名に含める。

## 構成

```markdown
## 仕事

### 取り組み名
- 実施したタスク。判断・理由・結果があれば同じ記録に含める。
- 関連するタスク。

## 個人開発

### プロジェクト名 / 取り組み名
取り組んだ課題・目的を短く記載。

- 自分が行ったこと。判断・工夫と、その理由や結果を含める。
- AIに任せた作業と、自分が提案・指示・確認した部分を区別する。

未完了・失敗・見送りで分かったことや次の対応を、必要なら補足。

## その他

### 取り組み名
- 手続き・学習・用事など、実施したタスク。

## 補足
必要な場合だけ、その日に残しておきたいこと。
```

「判断」「結果」を独立した必須欄にして同じ内容を繰り返さない。本人の実施を広く残し、日常業務に無理な成果・学びを付け足さない。個人開発では自分の貢献を読み取りやすくし、AIの成果をそのまま自分の実績に変えない。

## 視認性と出典

取り組みごとに見出しと段落で区切り、短い箇条書きで読む。余白は広め、要点だけ太字。Notionの標準の見出し・段落を使い、必要な区分間に空ブロックを一つ置く。すべての行間へ空ブロックを挟まない。ブラウザーのモックアップのCSSをNotion本文に埋め込まない。

末尾の「出典・記録範囲」は折りたたみ。参照リンクや会話ID、対象日の取得範囲・取得時点、資料ごとの主な欠落を短く記す。本文確認時は折りたたむ内容も本人に表示する。Notionの構文は保存直前に最新仕様を読む。

```text
<details>
<summary>出典・記録範囲</summary>
	対象日・取得範囲・取得時点。
	Langfuse、メール、PC活動記録の出典と欠落。
</details>
```

取得資料にタスクがなく、本人からの補足もなければ、活動区分を作らず「参照資料から具体的な実施タスクは確認できなかった」と補足する。「活動なし」とは書かない。
