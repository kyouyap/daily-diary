# 日誌本文の形式

ページ名は `YYYY-MM-DD` だけ。仕事・個人開発・その他の区分は活動があるものだけ表示する。プロジェクトはDB項目にせず、必要なら取り組み名に含める。

## 構成

```markdown
## 仕事

### 取り組み名
- 実施したタスク。判断・理由・結果があれば同じ記録に含める。
- 関連するタスク。

## 個人開発

### プロジェクト名 / 取り組み名
取り組んだ課題・目的を短く記載。

- 自分が行ったこと。判断・工夫と、その理由や結果を含める。
- AIに任せた作業と、自分が提案・指示・確認した部分を区別する。

未完了・失敗・見送りで分かったことや次の対応を、必要なら補足。

## その他

### 取り組み名
- 手続き・学習・用事など、実施したタスク。

## 補足
必要な場合だけ、その日に残しておきたいこと。
```

「判断」「結果」を独立した必須欄にして同じ内容を繰り返さない。本人の実施を広く残し、日常業務に無理な成果・学びを付け足さない。個人開発では自分の貢献を読み取りやすくし、AIの成果をそのまま自分の実績に変えない。

## 視認性と出典

取り組みごとに見出しと段落で区切り、短い段落・箇条書きで読む。余白は広めに取り、結果・判断など拾い読みしたい要点だけ太字にする。説明全体を太字にしない。

Notionでは活動区分ごとに、見出しとその区分の全タスクを一つの背景色付きcalloutへ入れる。仕事は `green_bg`、個人開発は `blue_bg`、その他は `yellow_bg`。色に加えて区分名も表示し、区分内の取り組み名は小見出しにする。活動がない区分はcalloutも作らない。「補足」があれば区分の外へ置く。

区分間と取り組み間に空ブロックを一つ置き、本文は標準幅にする。見出し直後はNotion標準の余白を使う。すべての行間へ空ブロックを挟まない。ブラウザーのモックアップのCSSをNotion本文に埋め込まない。

保存用の例（実際の構文は保存直前に最新仕様を読む）：

```text
<callout color="green_bg">
	## 仕事
	### 取り組み名
	- **確認できた結果・判断。**必要な説明を続ける。
	<empty-block/>
	### 次の取り組み名
	- 実施したタスク。
</callout>
<empty-block/>
<callout color="blue_bg">
	## 個人開発
	### プロジェクト名 / 取り組み名
	取り組んだ課題・目的。
	- 自分が行ったことと判断・理由・結果。
</callout>
```

calloutの子ブロックはタブでインデントする。確認用の全文は読みやすい通常の見出しで表示し、保存時の区分別背景色・要点の太字も伝える。確認後に要約や新しい結果を追加しない。

末尾の「出典・記録範囲」は折りたたみ。参照リンクや会話ID、対象日の取得範囲・取得時点、資料ごとの主な欠落を短く記す。本文確認時は折りたたむ内容も本人に表示する。Notionの構文は保存直前に最新仕様を読む。

```text
<details>
<summary>出典・記録範囲</summary>
	対象日・取得範囲・取得時点。
	Langfuse、メール、PC活動記録の出典と欠落。
</details>
```

取得資料にタスクがなく、本人からの補足もなければ、活動区分を作らず「参照資料から具体的な実施タスクは確認できなかった」と補足する。「活動なし」とは書かない。
