# 資料と初回設定

## 初回設定

`$CODEX_HOME/work-diary.json` を読む。CODEX_HOME未指定なら `~/.codex/work-diary.json`。このスキルはフォルダ単体で動き、元のリポジトリや個人用 `daily-diary.json` を必要としない。スクリプトはスキルフォルダの実体から絶対パスで呼ぶ。

会社側で次を設定する。設定がない場合は、会社用として参照する作業フォルダと、会社側のNotion保存先URLを一度に尋ねる。保存先が未定なら下書きまで進められる。会社用フォルダが未指定なら、その不足を示して他の確認できた資料と本人の話を使う。

```json
{
  "workspace_roots": ["/absolute/path/to/company-project"],
  "notion_destination": "会社側の保存先ページまたはDBのURL",
  "slack_user_id": null,
  "slack_channels": [],
  "notion_source_urls": []
}
```

これは設定の形の例。作業フォルダは絶対パスで明示し、会社の別プロジェクトや別worktreeも対象ならそれぞれ追加する。空の `slack_channels` は自動で全チャンネルを読む意味ではなく、本人の投稿を検索する既定にする。`notion_source_urls` は本人が指定する関連ページの補助リスト。

本人から指定された設定は会社PCのGit管理外の設定ファイルへ保存する。既存設定を保ち、認証情報は入れない。Slackの本人IDなど接続から確認できる値はツールで確認し、毎日尋ねない。個人版のNotion保存先・アカウント・Langfuse設定は参照しない。

## Codexの会話記録

公式に案内されている保存場所は `$CODEX_HOME/sessions` と `$CODEX_HOME/archived_sessions`。[公式説明](https://learn.chatgpt.com/docs/reference/troubleshooting)。同梱の `scripts/read_codex_day.py` をPython 3.12以上で使う。APIキーやLangfuseは必要ない。

```text
python3 -B <スキルの絶対パス>/scripts/read_codex_day.py \
  --start 2026-11-03T00:00:00+09:00 \
  --end 2026-11-04T00:00:00+09:00 \
  --workspace-root <会社用フォルダの絶対パス>
```

実行時は固定した対象期間と設定のフォルダを渡す。複数のフォルダは `--workspace-root` を繰り返す。必要なら `--codex-home` を明示する。日付のディレクトリは会話開始日なので、対象日のフォルダだけを検索しない。このスクリプトは全保存先からイベントの時刻と作業フォルダで絞る。

- `kind=user` は本人の発言、`assistant` はAIの報告、`tool_call` は呼び出し、`tool_result` は返された結果。結果本文を読んで実施状態を判断する。
- `source.path` と `source.line`、`session_id` が根拠。リンクを取得できなければ、CODEX_HOME相対のファイル名・行番号とsession IDを出典として残す。
- `next_offset` があれば同じ期間・範囲で `--offset` を渡して続きを読む。`truncated=true` の必要な記録は、元ファイルの該当行を追加で読むか、`--max-chars` を増やして読み直す。単一行のツール結果は大きい場合があるため、必要な部分から読む。
- `status=partial`、`issues`、本文省略はその制約として扱う。`read` はローカルの対象記録を読めたという意味であり、全業務や全PCの履歴が揃った意味ではない。
- 子エージェントの会話とシステム指示・内部推論は対象外。本人とAIの文章を二重計上するイベントの写しも重ねて採用しない。

記録がない・読めない・形式が変わっている場合は資料不足として進める。元のJSONLやCodexの記録設定を変更しない。クラウドや別PCの会話、画像・添付の内容、別サービスのClaude・ChatGPT会話を自動取得したとは扱わない。

## NotionとSlack

実行環境の接続済みツールを探し、本人の会社用アカウント・ワークスペースを確認する。未接続のサービスはその資料だけ不足として扱う。資料参照のために投稿や設定変更はしない。

Notionは指定された関連ページ、CodexやSlackに登場したページを読む。本人の記述や、本人が関与した設計・判断・議事録を拾う。最終更新時刻だけで当日の本人の作業とは断定しない。

Slackは本人の対象日の投稿・返信を中心に検索し、相談・提案・調整・支援を拾う。関連スレッドの他人の発言も文脈として読めるが、本人の行動と区別する。検索の日付境界が対象期間と違う場合は前後も検索して実際の送信時刻で絞る。ページ送りや取得上限を確認し、打切りは部分取得として残す。

## Computer History

Computer Historyのスキル・ツールが使える場合は手順を読み、記録状態を確認して対象日に重なる要約・イベントを参照する。会社用フォルダ・ページ・会話に関連する作業を拾い、私用の記録を混ぜない。記録開始時刻、途中の停止、欠落を確認し、画面表示・入力・保存・送信を区別する。記録開始・設定変更は日誌作成のために自動実行しない。

Computer Historyが使えなければ、その資料の不足を示して進める。要約だけで会話全文や全業務の実施を確認したとは扱わない。
