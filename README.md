# Daily diary

## 日誌の管理先

日誌本文は [Notionの個人業務日誌](https://app.notion.com/p/96f7af28509b4818b8f182a104650bcf) で管理します。[目的と記録ルール](https://app.notion.com/p/3f8d2916bbfe8104b720e2589964c197) もNotionにあります。

2026-10-13、9/30〜10/12の13日分を移行して本文とリンクを照合し、本人の指示でリポジトリ内の元の日誌・旧目次・期間まとめを削除しました。

このPCの `~/.codex/skills/daily-diary/` に日誌作成スキルを配置しました。`$daily-diary 今日の業務日誌をまとめて` で、資料収集 → 一問ずつ最大二問 → 本文確認 → 接続済みNotion MCPで保存、を進めます。本文確認前は日誌を書き込まず、保存後は読み戻して照合します。新しい日誌での実運用は未検証、定期実行は未設定です。以下は別のローカルhelperの実装範囲を説明します。

Codex のログに基づく出来事を、dot との短い会話で補って日記にするためのローカル helper。**現在は合成資料とローカル Git によるレビュー用実装です。本番の日記運用はまだ開始していません。**

## 実装済み

- JST 日付の固定、取得範囲・欠落・遅延の表示、対象 project/user/session の限定、重複除外。
- 資料の除外処理、質問を一問ずつ最大二問、無回答・送付結果不明で停止する状態管理。
- 全文の表示 ID・日付・版・SHA-256 に結び付けた承認。訂正後は再承認が必要。
- 承認した本文だけを一ファイルとしてローカル bare Git へ保存。手編集保護、保存結果不明時の照合と再試行。
- 標準ライブラリによる CLI と 36 テスト。Web アプリ、専用 DB、追加 LLM API、音声 API、外部依存はありません。

## 未実装・未確認

- 本 helper からの live Langfuse 取得 adapter。収集関数には fetch を注入できるが、CLI の prepare は合成 fixture 専用です。
- 実日記の GitHub 保存。save-local はローカル bare repo 専用で、HTTPS/SSH remote を拒否します。このリポジトリへの実装公開とは別の機能です。
- dot と helper の自動橋渡し、日次起動・通知、実資料での文章品質と一日 2〜3 分の負担。
- 本番対象本人/session、運用時刻、runtime の保持・バックアップ条件。

本人の返信であることは dot が現在の会話で確認する契約です。helper の `--human-confirmed` は確認宣言であり、本人認証機能ではありません。資料中の OK は承認にしません。除外処理は非定型の機密・人名の完全検出を保証しません。

## 検証

確認済み環境は Python 3.13 / Git 2.48。リポジトリ直下で実行します。

```bash
python3 -m unittest discover -s tests -v
python3 -m daily_diary.cli --help
```

テストは架空の資料と一時ローカル Git のみを使い、外部通信・実ログ・実日記を使いません。一時ファイルは終了時に除去します。

| テスト | 件数 | 守ること |
| --- | ---: | --- |
| core | 8 | JST 境界、承認本文の一致、状態破損で停止、同日ロック、専用場所への書込 |
| collect | 7 | 本人・期間の限定、ページ欠落を成功としない、重複除外、秘密形状とログ内命令の除外 |
| dialogue | 8 | 二問の上限、曖昧・古い OK の拒否、訂正時の承認失効、後着ログで本文を変えない、送付不明で再送しない |
| git_save | 10 | 承認 bytes だけの保存、手編集保護、重複 commit 防止、Git 設定・symlink による外部書込の拒否 |
| flow | 3 | CLI を通した表示→承認→保存の一致、翌日の再開、保存失敗を成功扱いしない |

小さな日記用途でも、誤保存・上書き・再質問・情報混入は避けたいので、その境界を試験しています。ケースを分けた結果が 36 件で、文章の出来や気持ちの正確さ、本番接続を証明する数ではありません。今回の公開作業でテストや仕組みは追加していません。
